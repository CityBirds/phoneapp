# 模板识别与手机表单自动生成整改说明

交付对象：Jules。日期：2026-09-29。

本说明整合本轮已确认需求与实现建议，补充同目录的问题报告和验收用例。当前代码复核基线为 a93f9c4。以下描述的是要实现的目标，不代表已经完成整改。禁止仅修改页面文案、增加型号分支或保存无执行用途的字段映射后宣称完成。

## 1 目标与当前缺口

目标：模板上传后，通过真实文档结构识别和人工确认形成已发布配置。手机按配置显示设备型号、文档组合、单值填写项及表格；服务端按相同配置校验，执行端按绑定位置写入原模板。新增适用范围内的设备型号和模板，不需要修改手机页面代码。

当前手机型号选项、证书字段、各型号测量点数组、POA200 清单物料、是否存在清单均主要写死。虽加载 /api/templates，但主要用于 POA200 传感器下拉选项，未用于构建完整表单。执行程序读取 fieldMappings 后也未将其传给生成器使用。必须打通配置到执行的完整链路。

手机的导航、终端选择、提交、历史、预览等页面外壳保持统一；由配置决定具体型号、填写内容、默认值、表格和生成文档。

## 2 完整业务流程

上传模板 → 选择已有型号或新增型号 → 指定证书/清单及适用选项 → 解析真实结构 → 用户指定需要配置的字段，程序辅助推荐 → 确认字段类型、值位置或表格范围 → 保存草稿 → 校验并试填预览 → 发布配置 → 手机加载配置生成表单 → 服务端验证提交 → 固定模板及配置版本 → 执行端写入 → 回传原文件 → 协调服务生成真实预览 → 历史保存结果。

上传不等于发布。仅被识别到的文字不自动成为用户必填项。没有把握的解析或映射必须待确认，不生成假坐标、假绑定或假成功。

## 3 文档结构识别

### 3.1 先解析真实 Word 结构

DOC 与 DOCX 都需支持，结果文件保持模板真实格式。DOC 使用能读取实际 Word 结构的解析路径；DOCX 正确解析其文档结构，不能直接对整个压缩文件搜索 XML。禁止把 DOC 二进制整体按 UTF-16 切片并固定每若干个文本拼成一行。

保留段落、表格、单元格顺序、空单元格、合并关系、单元格内换行和单位。定位信息必须与具体模板文件 hash/版本关联。解析失败明确提示，不降级为可发布的猜测位置。

这次提供的 990 证书，上方描述区和下方测量区实际属于同一个 Word 表格。因此必须识别同一表格里的不同区域，不能按“一个 Word 表格只对应一种表单”处理。合并单元格和排版间隔不能用固定列数推断。

### 3.2 单值区域

Date、Instrument、Inst. SN.、Ambient Temperature、Relative Humidity 等，属于标签对应单个值的位置。匹配时记录标签位置和值位置，不能仅记录标签坐标。

本次 990 证书的真实示例（Word 1 起始行列，仅适用于本文件版本）：

| 字段 | 标签位置 | 值位置 | 原内容 |
|---|---|---|---|
| Date | 表1 行4 列6 | 表1 行4 列7 | 8/28/2026 |
| Instrument | 表1 行6 列2 | 表1 行6 列3 | DPT-990-Ex |
| Inst. SN. | 表1 行7 列2 | 表1 行7 列3 | EX10260902 |
| Ambient Temperature | 表1 行7 列6 | 表1 行7 列7 | 22.1℃ |
| Relative Humidity | 表1 行8 列6 | 表1 行8 列7 | 50%RH |

同一行可存在多组标签和值。标签和值若在同一个单元格，应绑定可替换的具体范围并保留标签和单位；第一版未支持的布局应明确提示人工处理，不能覆盖整格冒充成功。

### 3.3 证书测量区域

以 Test point Number 作为主要识别特征。匹配时忽略英文大小写，统一连续空格和单元格内换行，因此 Test / Point / Number 分成多行仍识别为同一标签。

找到特征后，结合同行表头、下方连续测量点及各列对齐关系确定区域。NIST Traceable Standard 和 Analyzer 的文字与单位可能在同一单元格分行，应整体识别，再提取名称与单位。

这份 990 证书表头位于行12，数据为行13至21，共9行；测量点在列2，标准值在列3，实测值在列4。Analyzer 绑定的是下方9个值位置，不能绑定右侧邻格。区域在测量数据结束处停止，不包含下方说明、签名和印章。

测量行数、列数、列名、单位、标准值默认内容从模板及确认配置获取，禁止按型号写死1/10/9行或内置标准值数组。证书测量行第一版按已确认数据区显示，不因清单允许增删而自动开放测量行增删。

### 3.4 清单区域

以“序号”为主要识别特征，结合同行名称、规格/型号、数量、单位、标配、备注等表头及下方物料记录确定区域。单独出现“序号”二字不足以认定整片区域可编辑。

本次 990 清单为7列、11条物料，没有独立传感器行。清单默认物料、各列和空白值必须来自本模板，不得继承 POA200 数据。

普通物料允许新增/删除，名称可自行填写，序号自动连续；不提供排序功能。主设备行不能删除。POA200 模板中的传感器行不能删除，但不得为没有传感器行的模板虚构此行或强制要求它存在。新增行复制指定样板行的格式，正确处理分页。

以上特征用于自动推荐。无特征、多个候选或布局不确定时，允许人工选择正确区域，不能限制系统永远只能处理带固定词的模板。

## 4 字段类型与输入方式

### 4.1 本轮确认的自动推断规则

| 条件 | 建议类型 | 手机控件 |
|---|---|---|
| 单值字段标签含日期含义的 Date 或“日期” | 日期 | 日期选择框 |
| 普通单值字段，未配置更明确类型，如 Instrument | 文本 | 普通输入框 |
| 已确认的测量表格或清单区域 | 表格 | 放在单值区域后，按列和行呈现 |
| 已明确配置选项，如 POA200 传感器型号 | 枚举 | 下拉选择框 |

类型判断优先级：管理员明确配置 > 已确认表格/列结构及列配置 > 字段标签规则 > 普通文本。

英文 date 按词语或合理标签分词识别，不得把 Update、Candidate 等无关词中包含的字符 date 当成日期。支持 Date:、Certificate Date 等；中文支持证书日期等。存在歧义时推荐并待确认。

结构识别优先：表格中的日期列仍是表格的一列，每行使用日期控件，不能抽离成顶层单值。可供管理员设置数字类型和单位，但第一版不凭不可靠猜测把所有字段强制转成数字；设备序列号要保持文本，保留前导零。

### 4.2 默认值与格式

默认值可由管理员选择模板原值、空值或明确的日期默认策略。已经确认标准值可逐行修改，初始值来自模板；实测值不能自动沿用旧证书的实测结果作为新测量，默认留空待填。温湿度、序列号等明确其默认策略，不得继续塞入代码里的测试数据。

日期控件内部采用无歧义日期值，写回 Word 的日期格式单独配置。文件名日期沿用任务受理当天并固定，跨日重试不改名；证书日期是用户可选字段，不能与文件名日期混为一项。

温湿度等单位作为配置保存并展示，写回时避免重复追加℃或%RH。是否必填、允许值、长度、默认值、是否编辑均由配置决定，前后端使用同一规则。

### 4.3 识别与参与填写分开

Customer 可以被识别，但按既定要求保持模板原值，不生成可编辑字段，也不得被发货目的地覆盖。没有被配置为可写的内容保持原样。

发货目的地和 POA200 传感器型号可以仅用于文件命名，没有 Word 位置也合法；其用途应明确为命名参数，不得制造虚假的正文绑定。传感器型号和装箱清单的传感器序列号/规格相互独立。

## 5 管理端字段配置界面

支持添加/删除需要配置的字段、修改手机显示名、覆盖自动推断类型、配置默认值/必填/选项、选择真实值位置。下拉选项允许中文或英文逗号分隔录入，去除空项和首尾空格，保存为数组；默认值必须是有效选项。

表格配置应支持表头位置、数据范围、列绑定、列名称/类型/单位、样板行、保护行和增删规则。不能把清单所有列都保存成 singleFields。

候选展示分开提供：标签匹配依据、目标写入位置、模板原有内容、是否人工确认。单值显示一个原值，表格列显示多行示例。原值为空显示“空”；找不到位置显示“未绑定”。“100%标签匹配”不是“绑定正确”。禁止使用“已指定位置”冒充原值。

手工选择、保存草稿、重新打开后不能丢失。正式发布校验真实目标有效、类型和默认值合法、表格范围完整、重复或重叠写入无冲突；同一共享字段可绑定多个合法目标。命名参数不要求 Word 坐标。

## 6 型号与模板组合

型号使用稳定 modelId，显示名称、别名、文件名中的型号文字分开维护。上传时选择已有型号或明确新增型号，不能依靠随意输入字符串恰好相等来关联。

每个型号及适用选项对应模板组，明确每个角色实际选用的模板版本；同一角色多版本不能随意选择列表第一项。

| 可用的已发布文档组合 | 手机下拉显示 | 填写及产物 |
|---|---|---|
| 证书+清单 | 型号（带清单） | 两份配置的填写项与表格，生成两份文件 |
| 仅清单 | 型号（仅清单） | 清单所需填写项与表格，只生成清单 |
| 仅证书 | 型号（仅证书） | 证书所需填写项与测量表，只生成证书 |
| 无可用模板 | 不作为可提交选项 | 管理端展示待配置原因 |

POA200 带泵/不带泵仍保留适用选项，不能误配两种变体。是否有清单与是否有传感器字段分别配置，不能互相推导。

型号显示名不能决定读取哪个模板；例如管理员确认旧990与DPT-990-EX对应同一型号后，用modelId关联，修复历史兼容但不能把不相关型号自动合并。

## 7 手机页面自动生成

先选择执行终端，再加载该终端能够执行的已发布模板组，随后选择型号/适用选项。不能在手机里继续枚举固定型号。

页面内容顺序：设备与模板选择 → 共用单值字段 → 各文档专属单值字段 → 证书测量表 → 清单表格 → 提交区域。不存在的区域不显示。表格整体在单值填写项之后。

共用字段以稳定 fieldId 关联，例如设备序列号只填一次，写到证书和清单各自绑定处。不能靠显示标签恰好相同自动合并业务意义不同的字段；默认值冲突在管理端发布前解决。Instrument 显示为普通输入框时，初始值可来自模板；允许修改时应同步需要使用其值的标题和命名位置，但不改变任务绑定的modelId、模板或型号专属能力。

通用渲染器按配置选择文本框、日期框、下拉框和表格，而不是使用 if model === POA200 等型号条件生成内容。提交数据也按配置收集，不再按型号循环固定次数或固定提交 cert 文件。

刷新/重新进入时拉取新配置，新型号/新清单发布后无需重新部署手机页面。用户正在填写时发现版本变化，提示确认并保留兼容输入，不得静默清空或套用新版。

从配置显示的标签和选项按文本渲染，不拼接未经转义的HTML。手机不负责推断 Word 坐标，也不将任意路径或写入坐标作为可信执行参数发送。

## 8 建议的数据关系与执行契约

以下是实现建议，字段命名可调整，但语义必须覆盖：

- Model：稳定modelId、显示名称、管理员确认的别名。
- Template：templateId、文档角色cert/packing、版本、hash、真实格式、存储标识。
- PublishedBundle：bundleId/version、modelId、适用选项、实际文档引用、可用状态。
- Field：fieldId、显示标签、输入类型、用途、默认值、必填、枚举选项、文档写入绑定。
- TableRegion：regionId、真实表头和数据区、列配置、模板原始行、样板行、保护及增删规则。
- TaskSnapshot：已受理的bundle版本、每份模板和映射版本/hash、用户数据、固定命名日期与产物名称。

手机读取适合展示的表单配置；协调服务持有完整映射并权威验证。提交携带bundleId/version、业务fieldId及表格行数据，不信任手机自行添加的字段、路径或模板指针。

执行端按任务快照下载/缓存模板并校验hash；不能使用协调端绝对路径作为远程执行端本地路径，也不能找不到模板就回退samples。生成器真正执行已发布映射；保存的坐标必须适用于该模板版本。新增删除清单行时保持目标绑定有效，避免写入位置错位。

已受理任务继续使用受理时的组合。后来添加清单不会给历史证书任务自动补清单；排队、重试也不静默换新版模板。

## 9 文件结果和预览仍属于交付范围

源模板不修改。原文件生成成功并回传后才可下载；失败历史显示原因，不提供无效下载链接。

使用实际Word渲染得到PDF/图片，不以固定SVG重画替代。预览失败单独记录，不能标PREVIEW_READY或伪报任务成功。原文件存在时保留下载，预览重试仅转换原文件。刷新或重启后从同一历史仍能查看对应产物及所有预览页。

命名按已发布规则生成并保持模板扩展名。沿用既定覆盖确认、旧文件被打印任务引用时旧文件加副本后缀、新文件保持正式名称的规则。不自动删除历史文件。

## 10 建议实现顺序与验收

1. 实现真实结构解析，用本次990证书验证同一Word表格内的单值区与9行测量区；用990清单验证7列11条物料。
2. 完成字段/表格人工配置和类型推断，保存、重开、试填、发布均有效。
3. 建立模板组及统一标识，前端按已发布配置构建型号选项和表单。
4. 服务端校验与任务快照、模板分发、映射写入统一使用该配置。
5. 接通真实预览和历史恢复，按下面的新增场景及02文件的24条用例验收。
