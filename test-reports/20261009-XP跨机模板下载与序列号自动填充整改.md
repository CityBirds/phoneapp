# 测试报告：XP跨机模板下载与发货任务序列号自动填充整改

## 1. 任务背景与问题分析

根据用户反馈与移动端页面截图，系统运行在“183 协调服务电脑 + XP 独立执行端”架构下时，存在以下两个核心问题：

1. **问题 1：执行端报告 `Template path not found for model PGA500-Ex (cert)`**
   - **根本原因**：模板是在协调服务电脑（192.168.1.183）上上传配置的，数据库 `templates` 表中记录的 `filepath` 是协调服务本机的文件路径（如 `D:\York\phoneApp\uploads\templates\...`）。XP 执行端物理运行在另一台电脑上，该本地路径在 XP 机器上并不存在。
   - 当 XP 端的 `worker_xp.py` 尝试执行任务时，原逻辑直接检查 `os.path.exists(fp)` 为假；虽然有下载兜底，但原下载代码在保存本地文件时使用了包含中文字符的原始文件名 `found.get("filename")`，在 Python 2.7 / 3.4 32 位及 Windows XP CP936 环境下引发编码异常或路径解码失败，且被外层 `except Exception: pass` 静默吞掉，进而回退到本地不存在的 sample 目录，最终抛出 `Template path not found for model PGA500-Ex (cert)`。
   - 此外，协调端 `/api/templates/:id/download` 原使用 Express `res.download()`，在 Windows XP 的 Python HTTP 客户端接收中文 `Content-Disposition` 响应头时亦存在兼容性风险。
   - 手机端前端原错误横幅文案将执行端生成 Word 失败的错误粗暴归类为“预览转换失败 (原 Word 文档已生成并保存)”，造成误导。

2. **问题 2：检查发货任务的序列号是否会随着模板的不同自动填充序列号**
   - **检查结果与根因**：原前端 `extractDefaultDeviceSn(bundle)` 仅对证书模板的 `field_mappings.singleFields` 做了狭窄的英文字段匹配（`Inst. SN`），未能覆盖协调端保存发布快照 `bundle.config_snapshot` 中的中文标签（如 `出厂编号`、`设备编号`、`序列号`、`机身号`、`产品编号`），且未回退读取装箱清单主设备的序列号；在用户切换不同机型模板时，若未提取到则保留空值或未自动更新。

## 2. 修改与整改措施

### 2.1 XP 执行端模板获取与缓存整改 (`src/worker_xp/worker_xp.py`)
1. **三级模板匹配机制**：
   - 优先按任务绑定的稳定逻辑 ID `template_id` 精确匹配；
   - 其次按型号完全一致（忽略大小写）和文件类型（`cert` / `packing`）匹配；
   - 再次按纯字母数字规范化后的子串包含匹配（例如 `PGA500-Ex` ↔ `PGA500`）。
2. **本地缓存优先与跨机纯 ASCII 安全缓存文件名**：
   - 自动在执行端工作目录维护 `cached_templates/` 目录；
   - 缓存文件名统一使用纯 ASCII 标识 `tmpl_<id><ext>`（如 `tmpl_pga500_cert.doc`），彻底根除 Windows XP / Python 2.7/3.4 对中文路径和文件名发生的 `UnicodeEncodeError`；
   - 命中本地非空缓存时直接复用，不重复下载，支持网络断开下的离线生成。
3. **消除静默异常与增加详尽日志**：
   - 移除 `except Exception: pass`，记录详细的 HTTP 状态码与异常原因，便于现场诊断。

### 2.2 协调服务端安全下载接口整改 (`src/backend/server.js`)
1. `/api/templates/:id/download` 改用标准 `res.sendFile()`，并提供标准兼容的双重 `Content-Disposition` 响应头：
   - 针对 XP / 旧客户端：`filename="${safeAsciiFilename}"`；
   - 针对现代浏览器：`filename*=UTF-8''...`。

### 2.3 手机端发货任务序列号自动填充与状态呈现整改 (`src/frontend/app.js` & `index.html`)
1. **全字段智能提取 `extractDefaultDeviceSn(bundle)`**：
   - 深度解析 `bundle.config_snapshot`、`certTemplate`、`packingTemplate`、`packingRowRoles` 及 `packingItems`；
   - 扩充序列号正规表达式，全面支持：`/Inst\.?\s*SN|出厂编号|设备编号|机身号|产品编号|设备序列号|序列号|Instrument\s*SN|SN[:：]|deviceSn|serialNo|serialNumber/i`；
   - 同时匹配字段标签（`label`、`name`、`key`）与预设候选值（`defaultValue`、`candidateValue`、`value`）。
2. **随模板切换实时自动填充与提示**：
   - 手机端下拉选择型号模板（`onModelChange`）时，自动将提取到的序列号填入 `#device-sn`；
   - 在序列号输入框下方动态展示友好提示：`ℹ️ 已随所选模板自动填充默认序列号：${extracted}`；
   - 当操作员手工修改序列号时，即时提示 `✏️ 用户已手工修改序列号为：${val}`，并联动同步装箱清单主设备备注中的 `SN: xxx`。
3. **手机预览与原件生成状态精准区分**：
   - 前端区分 `status === 'FAILED'`（执行端 Word 原件生成失败）与 `PREVIEW_FAILED`（原件已生成但仅预览转 PDF/图片失败），准确向用户呈现失败真实原因。

### 2.4 测试套件修复与新用例验证
1. 在 `tests/test_worker_xp_protocol.test.js` 新增 `XP-D06` 用例，模拟远程协调端模板下载、三级型号容错匹配、纯 ASCII 缓存文件生成及 Word 生成全流程；
2. 修复 `tests/test_e2e.test.js` 和 `tests/test_remediation.test.js` 中 `test.before((done) => ...)` 遗留未调用 `done()` 导致的测试挂起隐患；
3. 为 `src/backend/pdf_to_png.ps1` 增加 `Exit-Script` 强制进程退出并补齐 UTF-8 BOM，消除 Windows PowerShell 5.1 解析中文及 WinRT 线程残留问题。

### 2.5 标准Node.js执行端逻辑双向对齐 (`src/worker/worker.js`)
为确保 XP 独立执行端与标准 Node.js 执行端（多端接入、车间装配电脑等）行为完全一致，同步对 `src/worker/worker.js` 中的 `fetchTemplateForTask` 进行了对称整改：
1. **三级型号与模板匹配机制**：
   - 优先按精确 `templateId` 匹配；
   - 其次按型号全称规范化（`String(model).trim().toUpperCase()`）与 `fileType` 严格匹配；
   - 再次按纯字母数字清洗子串包含匹配（`cleanTmpl in cleanModel || cleanModel in cleanTmpl`）。
2. **纯 ASCII 安全缓存命名与离线复用机制**：
   - 路径统一保存在 `cached_templates/${found.id}${ext}`；
   - 优先检查本地非空缓存文件，存在即直接复用；
   - 缺失时通过 `/api/templates/:id/download` 下载并缓存，仅在下载异常时才对本地同名盘符路径进行软回退；
   - 彻底消除了不同执行端机器上的中文文件名乱码与重复网络拉取开销。

## 4. 现场使用与更新指引

1. **协调服务（183 电脑）**：
   - 重新启动协调服务（双击运行 `启动协调服务.bat`），确保 `/api/templates/:id/download` 接口与手机端前端最新脚本生效。
2. **XP 执行端电脑**：
   - 将更新后的 `src/worker_xp/worker_xp.py` 覆盖到 XP 电脑执行端目录（若使用源码运行直接覆盖后重新运行 `启动XP执行端.bat`；若使用单文件 exe 则重新运行 `一键打包XP执行端.bat` 生成最新 `worker_xp.exe`）；
   - 执行端首次执行对应型号任务时，会自动从 183 协调端下载模板并缓存到本地 `cached_templates/` 目录，之后即可长期稳定使用。
3. **标准 Node 执行端电脑（如其他Win10/Win11执行电脑）**：
   - 若在其他电脑上使用标准执行端（`npm run worker` 或 `启动执行端.bat`），同步更新 `src/worker/worker.js` 即可享受完全一致的三级匹配、纯 ASCII 安全缓存及离线复用能力。
4. **手机端操作**：
   - 在手机浏览器刷新页面，切换到 `PGA500-Ex`（或其他机型），界面会自动填入该模板默认的设备序列号，并展示提示信息；
   - 填写数据后提交任务，各执行端正常接收并完成 Word 生成，协调端自动转 PDF 与分页图片提供手机无插件预览与调度打印。
