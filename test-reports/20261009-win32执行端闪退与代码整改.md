## 一、整改前后对比证据

### 1. 启动器换行与未转义括号问题（XP-L01, XP-L02）
- **修改前**：`启动XP执行端.bat` 为 LF 换行，`echo 若在 XP 环境... (32位)。` 中的右括号提前闭合 `if errorlevel 1 (...)` 语句块，cmd 抛出 `此时不应有 。` 语法错误，窗口未执行 `pause` 直接退出（闪退）。
- **修改后**：批处理文件全面转换为 CRLF 换行；消除括号冲突；隔离运行在模拟缺少 Python 时，控制台清晰输出：
  ```text
  [ERROR] Python environment not found and worker_xp.exe not found.
  [ERROR] 未检测到 Python 环境且未发现 worker_xp.exe。
  [TIP] If on Windows XP, please install Python 3.4.4 32-bit or run build_xp.bat.
  [提示] 若在 XP 环境，请安装 Python 3.4.4 32位版本 或运行 src\worker_xp\build_xp.bat 打包。
  请按任意键继续. . .
  ```
  正常等待按键并返回退出码 1，彻底杜绝闪退。

### 2. 源码与打包 exe 配置位置不一致（XP-L03）
- **修改前**：源码模式配置保存在工程根目录，打包 exe 模式保存在 `src/worker_xp/dist/`，导致不同运行方式生成两个独立身份或重启回落 localhost。
- **修改后**：`get_base_dir()` 统一检测工程根目录，优先沿用并同步已有身份与配置，保证源码与打包模式身份单机唯一。

### 3. Python 2.7 中文编码断裂（XP-L04, XP-L05）
- **修改前**：`print("... %s" % str(self.name))` 以及保护行 `str(item.get('name'))` 在 Python 2 环境对包含中文的 unicode 对象调用 `str()`，抛出 `UnicodeEncodeError: 'ascii' codec can't encode characters`。
- **修改后**：统一采用 `to_unicode()` 与 `safe_str()` 处理编码边界，所有中文字面量补充 `u'...'` 前缀，中文名称、路径与表单字段不再引发崩溃。

### 4. 损坏配置与保存状态伪报（XP-L06）
- **修改前**：`load_json_file` 捕获异常直接返回 `None`，将损坏配置文件误判为初次运行并覆盖；保存失败依然置 `saved_on_machine = True`。
- **修改后**：读取异常明确抛错并拒绝生成替代身份；仅在真正写入成功后才置 `savedOnThisMachine = True`。

### 5. 模板文档生成失败被伪报成功（XP-L07）
- **修改前**：COM 调用失败后仅向 stderr 输出 notice，对于 `.doc` 文件不抛异常，直接返回 `success=True`，导致未填写的空白模板副本当作已生成成件上传。
- **修改后**：增加严格的生成校验（XP-L07）；当 COM/docx 引擎不可用且未写入时，立即清理输出文件并抛出明确错误，上报 `file-failed`，绝不把空模板误报成功。
