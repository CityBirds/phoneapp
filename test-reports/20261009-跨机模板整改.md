## 1. 整改背景与核心问题

根据《跨机模板异常诊断报告_20261009.md》，在协调端集中管理与远程执行端（64位及32位Windows XP）跨机协同场景下，存在以下系统性缺陷：
1. **执行端依赖协调机本地路径**：协调机上传模板后存库路径为 `D:\York\phoneApp\uploads\...`，执行端直接访问抛出 `Template path not found`；
2. **下载权限控制缺陷**：原 `/api/templates/:id/download` 依赖手机端凭证，执行端无手机凭证时受阻；
3. **模糊匹配与非法兜底风险**：原 `fetchTemplateForTask` 在模板缺失时通过子串模糊匹配或回退到本地 `samples/` 目录，导致非当前型号模板被错误使用；
4. **缺少任务模板快照冻结机制**：协调端若删除或更新模板，在途任务或重试任务可能发生版本漂移或由于文件不存在而崩溃；
5. **缓存篡改与伪装风险**：未对下载和本地缓存执行 SHA256 与非 HTML/JSON 伪装校验；
6. **证书与装箱清单排版结构损坏**：
   - 证书测量表被增删行或表尾说明被截断（违反固定行数和逐格填值规范）；
   - XP 端硬编码写死 R4C6（Date）与 R7C2（SN），破坏模板原有布局；
   - 装箱清单写死 7 列物理结构，未随模板实际表头自适应；
   - 主设备备注存在 `SN: SN: ...` 重复前缀问题。

## 2. 详细整改措施

### 2.1 数据库结构与快照冻结机制 (`src/backend/db.js`, `src/backend/server.js`)
1. **任务文件快照迁移**：在 `task_files` 表新增列：
   - `template_id TEXT`: 任务受理时绑定的模板唯一标识；
   - `template_hash TEXT`: 模板文件的 SHA256 校验和；
   - `template_version TEXT`: 模板发布版本号；
   - `template_size INTEGER`: 模板文件字节数；
   - `field_mappings TEXT`: 任务绑定的不可变字段坐标映射快照。
2. **提交任务时原子冻结 (`POST /api/tasks/submit`)**：
   - 根据任务绑定的机型 `model` 与 `docCombo`，从 `templates` 检索当前发布的模板及其哈希、版本与字段映射；
   - 插入 `task_files` 时持久化上述 5 项元数据，形成不可篡改的历史快照；
   - 即使协调端后续更新或删除了该模板，任务执行与重试始终使用任务创建时的冻结快照。
3. **专属任务模板下载接口 (`GET /api/worker/tasks/:id/templates/:fileType`)**：
   - 仅允许持有合法 Worker Token 的执行端访问；
   - 严格检验任务归属（`task.worker_id !== claimingWorker` 立即返回 403 `TASK_WORKER_MISMATCH`）；
   - 校验物理文件 SHA256 哈希，若与快照不符拒绝分发；
   - 响应头携带 `x-template-hash` 与 `x-template-version`；
   - 记录审计日志，不泄露认证凭据。
4. **访问控制放行 (`src/backend/access_control.js`)**：
   - 将 `/api/templates/:id/download` 加入 Worker 专用白名单，允许执行端使用 Worker Token 下载已发布的公共模板，无需手机端 Token。

### 2.2 64位执行端整改 (`src/worker/worker.js`, `doc_processor.ps1`, `doc_processor.py`)
1. **模板拉取与安全缓存 (`fetchTemplateForTask`)**：
   - **移除所有 `samples/` 兜底与直接读取协调机本地绝对路径的行为**；
   - **优先级 1**：通过任务专属端点 `GET /api/worker/tasks/:taskId/templates/:fileType` 下载；
   - **优先级 2**：若专属端点返回 404，通过标准 Worker 鉴权从 `GET /api/templates/:templateId/download` 下载；
   - **禁止子串模糊匹配**：仅支持精确匹配或规范化前缀匹配（如 `POA3500` 与 `3500`）；
   - **完整性校验**：下载写入 `.tmp` 临时文件，校验文件大小 > 0、首部非 `<html` / `{` 伪装且 SHA256 校验通过后，原子重命名为 `cached_templates/tmpl_<id>.doc`；
   - **缓存失效**：发现缓存损坏、哈希不匹配或伪装时，立即自动删除缓存重新下载。
2. **PowerShell 处理器 (`doc_processor.ps1`)**：
   - **UTF-8 BOM 修复**：确保脚本采用 UTF-8 with BOM 编码保存，杜绝 Windows PowerShell 5.1 在解析中文及非 ASCII 字符（如 `℃`）时发生语法解析中断；
   - **装箱清单动态列检测**：根据表头行内容自适应识别序号、名称、规格、数量、单位、标配与备注列，不再硬编码 1..7 列；
   - **主设备位置自适应**：支持主设备行位于非第 1 行的情形；
   - **去重单次 `SN:` 格式化**：生成主设备备注时先清除原有 `SN:` 或 `SN：` 前缀，严格格式化为 `SN: <设备SN><带泵信息>`，避免产生 `SN: SN: ...`。
3. **Python 处理器 (`doc_processor.py`)**：
   - 支持动态列表头同步（`header_r` 与 `columns` 遍历同步）；
   - 智能单字段扫描（`Date:`、`Inst. SN.`、`Instrument`、`Ambient Temperature`、`Relative Humidity`）写入邻近数据格，不破坏标签文字；
   - 保护表尾认证声明与签字行。

### 2.3 32位XP执行端整改 (`src/worker_xp/worker_xp.py`, `word_engine_xp.py`)
1. **Python 2.7 / 3.x 语法严格兼容**：
   - 严禁使用 f-string、类型注解（`def foo() -> int:`）、`async / await`；
   - 使用 `unicode` / `safe_str` 安全编码转换，杜绝 Windows XP CP936 下的 `UnicodeEncodeError`；
   - 使用标准 `%` 格式化与标准库 `urllib2` / `requests`。
2. **XP 模板拉取机制 (`fetch_template_for_task`)**：
   - 从任务专用端点或 `template_url` 下载；
   - 纯 ASCII 安全缓存命名（`tmpl_<id>.doc`）；
   - 校验 SHA256 与非 HTML/JSON 伪装，支持 `.tmp` 原子重命名；
   - 严禁 samples 兜底与协调端绝对路径本地回退。
3. **XP Word 引擎深度重构 (`word_engine_xp.py`)**：
   - **废除硬编码写入**：废除硬编码 R4C6 与 R7C2，废除全文查找替换 `AP10007513`；
   - **智能标签位置检索**：全表扫描查找 `Date:`、`Inst. SN.`、`Instrument`、`Ambient Temperature`、`Relative Humidity` 标签单元格，定位后将值写入下一邻近单元格，保留标签单元格原生内容；
   - **固定行数校验 (`validate_cert_fixed_rows`)**：证书测量表行数必须严格等于模板配置的固定数据行数，不匹配立即报错，禁止静默增删行或删除表尾；
   - **装箱清单保护行校验与动态列 (`detect_packing_columns`, `validate_packing_protected_rows`)**：检测表头动态索引，保护主设备与传感器行，支持非首行主设备；
   - **回写验证机制**：文档保存后，从 Word 物理表格读回关键字段（`device_sn`、`cert_date`），验证通过后方可返回成功；
   - **COM 进程资源守护**：在 `try...finally` 中显式执行 `doc.Close(False)`、`word.Quit()` 与 `pythoncom.CoUninitialize()`，杜绝 XP 下 WINWORD.EXE 僵尸进程泄漏。

## 5. 验收结论与部署建议

1. **验收结论**：
   - 协调服务端与 64 位执行端跨机模板拉取、安全鉴权、快照冻结机制整改完毕，所有历史及新增用例 100% 通过；

2. **部署使用说明**：
   - **协调端**：直接重启协调服务即可（数据库迁移自动生效，在 `task_files` 自动增加快照字段）；
   - **64位执行端**：更新 `src/worker/` 目录文件，启动执行端；模板拉取将自动走安全鉴权与 ASCII 缓存流程；
   - **32位XP执行端**：将包含修复后 `src/worker_xp/` 的更新包拷贝至 XP 机器，运行一键启动脚本即可，跨机模板下载与序列号自动填充已全部打通。
