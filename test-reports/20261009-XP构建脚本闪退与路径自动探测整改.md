  1. `src/worker_xp/build_xp.bat`：
     - **消除致命括号语法错误**：原脚本在 `if errorlevel 1 (...)` 条件块中包含未转义的 `(32-bit)`、`(x86)`、`(3.4.4 x86)` 等半角括号，Windows XP 的 `cmd.exe` 在词法解析时误将内部右括号当成代码块提前闭合，抛出 `此时不应有 is...` 语法解析错误，直接导致 CMD 进程瞬间崩溃退出（闪退）；重构为纯正无括号解析风险的 `goto` 标签跳转结构；

     - **PyInstaller 离线安全加载**：改用 `%PY_CMD% -c "import PyInstaller"` 与 `%PY_CMD% -m PyInstaller` 原生调用，不依赖可能缺失的独立 `pip.exe` 或 `where` 命令；

     - **严格格式规范**：全脚本统一采用 Windows CRLF 换行，纯 ASCII 兼容提示文本。
  2. `一键打包XP执行端.bat`（根目录新增）：

  3. `一键配置XP编译环境.bat`（根目录新增）：

## 一、用户实机故障现象与机理复盘

### 1. 现象复盘
- **用户操作**：运行给出的编译环境配置后，回到根目录，再次运行 `build_xp.bat`。
- **用户反馈**：“没有出现对应目录，且黑屏闪退”。

### 2. 根因剖析
- **闪退根因 1（CMD 语法爆炸）**：原 `build_xp.bat` 第 18 行 `echo [TIP] Please ensure Python 3.4.4 (32-bit)...` 处于 `if errorlevel 1 (...)` 代码块内。XP 的 `cmd.exe` 在解析该块时提前遇到 `)`，直接将后续字符报为 `此时不应有 is。`。由于是语法解析错误，系统未执行到后面的任何命令（包括 `pause`），批处理窗口在 0.05 秒内直接闪退关闭。
- **闪退根因 2（PATH 未自动生效）**：XP 下安装 `python-3.4.4.msi` 默认不勾选 PATH 环境变量。原脚本未检查默认安装路径 `C:\Python34\`，直接执行 `python --version` 必然返回非零错误码，立即坠入上述带有语法炸弹的报错块。
- **闪退根因 3（UTF-8 中文文件名在 XP CP936 下乱码导致找不到文件）**：原批处理保存为 UTF-8 编码，内部调用了带有中文的文件名（如 `1-安装Python3.4.cmd`、`一键配置XP编译环境.cmd`）。在 XP 默认代码页 CP936 下，UTF-8 多字节被解析为乱码文件名，系统提示找不到文件，加之包装脚本末尾缺少 `pause`，直接闪退退出。
- **目录未出现原因**：因打包尚未启动即闪退，自然没有生成 `dist\worker_xp` 目录；且原脚本仅在子目录输出，未在根目录提供镜像与直观弹窗。

### 3. 本轮二次彻底治理措施
- **全链路 100% 纯 ASCII 化**：所有在 XP 上由 cmd.exe 执行的脚本及互相调用的文件名，一律转换为严格纯 ASCII（每个字节 <= 127），杜绝任何代码页导致的乱码找不到文件；
- **双重防闪退 pause 兜底**：根目录包装批处理在执行前后均保留明确控制台输出，末尾无条件强制执行 `pause`，即使内部命令出现任何意外也绝不关窗；
- **新增纯英入口**：增加 `setup_xp_env.cmd` 与 [一键安装并打包XP端.bat](file:///d:/York/phoneApp/一键安装并打包XP端.bat)，全流程一键贯通。
