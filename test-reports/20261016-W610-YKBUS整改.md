## 2. 修改文件清单与数据库兼容策略

### 修改文件清单
1. `src/worker/poa200_protocol.js`：实现 YKBUS 18 字节 packed 帧编解码、20 字节向量校验、`CALVALUE_O2` 112 字节解包、`INFO_DEVICE` 248 字节解包/安全带原块打包，以及模块化传输适配器。
2. `src/worker_xp/poa200_protocol_xp.py`：Python 32 位 XP 兼容版本（无 f-string、无 type hint、无 async/await），实现一致的 YKBUS 帧编解码、`CALVALUE_O2` 112 字节解包与安全打包。
3. `src/worker/worker.js`：P0 写前重新读取原始 `INFO_DEVICE` 块，校验身份与完整性；仅修改许可字段 (`SnNo`, `OutDate`, `ChangeParFlag`)；写后回读核验 target/non-target 字段；O2 读取失败明确区分状态不伪造 error 标定 JSON 文件；解决 probe 无凭据问题。
4. `src/worker_xp/worker_xp.py`：对齐 Python 32 位 XP 端 P0 写前安全读取、写后回读核验、O2 失败不伪造文件及 Dedicated W610 设备清单拉取逻辑。
5. `src/backend/server.js`：增加 `GET /api/worker/w610/devices` 保护接口；解耦 `template-configs`，严格按 `doc_type IN ('cert', 'packing')` 筛选，防止通信配置当作模板；增加 w610 任务租约超时恢复 (60s)；保证任务回报幂等。
6. `src/frontend/admin.js`：模板配置表格严格按 `doc_type` 区分发货证书与装箱清单，通信配置单独位于 W610 通信配置区域。
7. `TEST.md` & `AGENTS.md`：更新当前规范入口和 W610 整改要求引用。

### 数据库兼容策略
- 保持现有 `worker_save_configs` 表结构与历史记录完全兼容，`doc_type = 'comm'` 的记录保留其授权路径、版本和检查状态，不作破坏性迁移。
- 模板接口只查询 `doc_type IN ('cert', 'packing')`，消除通信配置在模板列表误显示为孤儿模板的问题。

### 待补充协议资料清单
1. **MAX_DATA_LENGTH 与变长帧规则**：附件定义 `data[MAX_DATA_LENGTH]`，有载荷时外层 CRC 的确切偏移位置需带数据实测帧进一步确认。
2. **CALFILE 结构体长度矛盾**：附件结构体按 `uint32 ptCnt` + 16 * CALPOINT 算为 196 字节，而尾注标记 "132"，需要厂家确认固件版本。
3. **W610 实际传输协议**：需向设备厂家确认实际固件是支持 TCP 透传还是特定的 HTTP 桥接，以及端口与串口波特率配置。
