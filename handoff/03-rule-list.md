# 规则清单 v1.0

日期：2026-09-27。本文件整合通用和模板规则，替代此前讨论稿作为本交付包的引用来源。R／T为基线要求，D为待确认决策。实现细节可以由开发方提出，但不得改变基线业务效果。

## 1. 身份、资源和范围

| 编号 | 规则 |
| --- | --- |
| R01 | 首次手机登记姓名，以后沿用，改名在协调服务；一人多手机分别登记。姓名不作为唯一客户端标识。历史保留提交当时姓名，另记取消、重试操作者 |
| R02 | 首版不划分用户角色；所有已接入手机可查看所有人的任务及预览，可取消所有人的任务；是否重试他人任务见D01 |
| R03 | 执行端本机配置允许的业务根目录及子目录范围、打印机等资源；协调端和手机不能扩大。请求到执行端必须再次校验。业务文件浏览、生成、读取与打印来源均受边界限制 |
| R04 | 稳定资源身份不能仅由IP或显示名称决定。同一物理打印机由一个执行端负责并共用一个队列；打印权限不等于开放任意文件或系统配置 |
| R05 | 系统库、驱动、日志、专用缓存可按运行需要使用，但不开放任意文件接口。路径跳转、链接和文档外部引用不能成为越界入口；无通用远程命令执行功能 |
| R06 | 串口首版仅占位，任何实际串口操作请求均不可执行 |

## 2. 提交、排队及恢复

| 编号 | 规则 |
| --- | --- |
| R07 | 设备忙碌时允许进入和填写；点击提交时提示排队，确认后再次校验并受理。弹窗不占队列位置，显示队列长度只代表当时状态 |
| R08 | 以协调服务持久记录并正式受理的先后顺序排队，不按手机时间、打开页面时间或开始填写时间排序 |
| R09 | 同一次提交网络重发／重试保持同一内部请求身份，不重复受理执行；用户明确“再做一次”才创建新的业务执行。保留内部标识，不提供旧提议的业务显示任务编号 |
| R10 | 提交后回复丢失显示“正在确认是否已接收”，查询或重发原请求；超时不等于未执行，不自动创建另一打印任务 |
| R11 | 提交前执行电脑已离线，不接受新任务；手机保留填写内容，重连不自动提交草稿 |
| R12 | 已受理而尚未下发的任务在断线时保留暂停；恢复后检查模板、文件、覆盖许可及资源。已下发而结果不明进入“结果待确认”，不能当作未执行重做 |
| R13 | 手机关闭或断网不阻断已受理任务；重新打开查询原任务结果，不要求手机持续在线 |
| R14 | 所有人可取消单项或批次中尚可停止部分。未下发可取消；已下发／已执行须确认停止才显示取消成功，已发生的打印不能撤回；取消与下发竞态必须协调 |
| R15 | 不同执行电脑可并行生成。同一电脑允许生成一份文档并打印另一已生成文件；对同一文件或互斥办公组件协调，不能把全网统一串行化 |
| R16 | 协调服务和执行端保存足以恢复及去重的状态；重启后核对任务阶段及执行记录，不能盲目重放已下发任务。具体存储和协议由开发方设计并测试 |

## 3. 文件、预览、打印和错误

| 编号 | 规则 |
| --- | --- |
| R17 | 模板原件始终不被生成任务修改或删除。.doc/.docx生成的真实格式和扩展名与模板一致；图片／PDF只是单独的预览 |
| R18 | 普通同名输出展示文件及可取得的更新时间等，确认后覆盖；实际写入前复查，若确认后内容已变化，暂停并重新确认，不影响无关任务 |
| R19 | 旧文件已有打印任务等已确定的版本保护冲突时，旧内容改名为同目录“原名-副本（1）.doc”等；序号递增不覆盖已有副本，新结果永远用模板规则正式名。不能给新结果加副本后缀 |
| R20 | 旧任务仍绑定旧内容及副本位置，归档时维护打印与预览关联；同名并发须协调。打印程序或外部程序占用导致不能安全改名时暂停，不强行关闭程序或强行覆盖 |
| R21 | 生成、保存、回传、预览分阶段记录。保存失败说明环节、目标和已知原因；原因不明如实显示，不编造。建议先完成新结果再替换；保护源模板不等于旧结果保护已自动实现 |
| R22 | 预览失败只重试转换或必要回传，不重新生成；预览绑定内容版本。仅预览旧结果被普通覆盖时的历史保留和打印策略见D03，绝不静默打印另一内容版本 |
| R23 | 手机可从当前执行电脑允许范围内选择已有文件或系统生成文件，多选并逐文件指定份数；首版不提供手机任意上传或跨电脑文件选择 |
| R24 | 预览提供“确认并打印”；执行电脑打印对应原Word，不擅自改为PDF。打印参数及可打印扩展格式见D06 |
| R25 | 打印批次提交前可调整文件顺序，同一批按序处理，不主动插入其他用户批次。此顺序仅约束本系统，外部程序打印作业不受本系统保证 |
| R26 | 单文件错误且确认尚未产生打印副作用，可标记失败并继续其他文件；设备故障或结果不确定暂停该打印机后续调度，不重打已成功部分 |
| R27 | 打印区分已受理、已下发、已提交系统打印队列、能证实的完成或失败、结果待确认。没有可靠出纸反馈不得显示“已出纸完成”，也不要求凭无法取得的信号无限等待 |
| R28 | 失败先展示原因和阶段，再提供重试；点击需确认“已清除问题原因”，并复查可验证条件。打印结果不明须核对，确认故障清除不等于确认尚未打印 |
| R29 | 两文档必须分别记录阶段及状态，一份失败不能将整套显示成功；重试成功部分不得重复执行。部分打印及整套保存策略见D02 |

## 4. 历史与维护

| 编号 | 规则 |
| --- | --- |
| R30 | 使用协调服务北京时间；今天为当天00:00至查询时刻，本周为周一00:00至今，本月为当月1日00:00至今；按自然日历月长、闰年和跨年计算，不是滚动7／30天 |
| R31 | 文件、副本、预览、任务记录、日志暂不按期限自动删除，后续人工维护；明确确认的普通同名覆盖不属于定时清理，仍按R18执行 |
| R32 | 文件人工改名、删除或修改时显示实际可用性；不让旧路径默默指向新内容。磁盘不足报告故障，不自动删除业务文件腾空间 |
| R33 | 记录任务／请求内部标识、来源客户端及当时姓名、目标电脑和资源、模板版本、时间、阶段、错误及操作发起者；日志格式由开发方选定，不能泄露凭据和无关正文 |

## 5. 模板配置与具体业务

| 编号 | 规则 |
| --- | --- |
| T01 | 一台设备由证书和清单组成；手机选型号和带泵选项后显示两份模板对应字段。型号和设备序列号关联两份文件，建议共同数据只填一次 |
| T02 | Word原模板在协调服务管理，执行端负责生成和打印。手机根据发布配置动态显示表单；配置、Word和执行端匹配才执行，不匹配提示更新或暂停，不套用任意新版 |
| T03 | 用户先列需要配置的字段，程序据此匹配候选，展示位置、邻近标签及样例，用户选择确认；多个候选不自动定案，无候选可人工指定。支持忽略标签换行、空格、冒号等形式差异；不执行文档中的指令 |
| T04 | 单值和表格列分开配置。Analyzer pv ppm及Analyzer Under Test mA按数据区域逐行填写，标准值与实测值绑定同一测试点；表头及合并说明不是数据行。POA样本1行也用表格，DPT810样本10行；证书测试点增删未开放 |
| T05 | 标准值默认所选模板对应行的值，逐行可改，生成使用最终提交值；不得强制恢复模板值。此默认值许可不自动扩展到旧实测值、序列号、签名或其他内容 |
| T06 | 清单可新增／删除普通物料，不提供手动排序，序号自动连续。主设备行和传感器行不可删除，校验不能只靠隐藏按钮；按配置行身份保护，不依赖会变化的显示序号。新增行保持模板样式但不复制旧SN等业务内容 |
| T07 | 设备型号改变时，证书Instrument、清单标题及主设备型号、两文件名一起对应改变。设备序列号与传感器序号分开，文本保留前导零 |
| T08 | 201N200258称传感器序号；PSR-12-223(封装）为传感器型号，独立下拉选择，选项由协调服务配置，不自动联动清单规格／型号PMT210SEN。DPT810参考仪器Serial #07不得被设备SN替换 |
| T09 | POA200清单文件名仅设备型号为POA200时加(140)，换其他型号不加；不把(140)附加到证书名、正文设备型号或清单标题 |
| T10 | 带泵选项决定两文件名是否带“带泵”；不带泵时还删除清单主设备备注中的“带泵”，保留设备SN及其他内容 |
| T11 | 文件日期取协调服务受理当天北京时间，yyyyMMdd，跨日排队和重试不改名。证书日期独立输入，具体正文显示格式见D07 |
| T12 | 新型号在已有单值、下拉、表格、清单增删及条件命名能力内走配置，无需改程序；新计算、绘图或新设备控制能力不属于任意配置自动支持范围 |

### 已明确命名

POA200证书：

`{设备型号}证书{设备序列号}-{文件日期:yyyyMMdd}发{发货地}订单-{传感器型号}{带泵后缀}{模板扩展名}`

POA200清单及该模板改型号：

`{设备型号}{设备型号为POA200时加(140)}{设备序列号}发货清单{文件日期:yyyyMMdd}{带泵后缀}{模板扩展名}`

其他型号可配置为`{设备型号}{分隔符}{设备序列号}发货清单`／`发货证书`，但空格或连字符、是否含日期与附加字段按各模板配置，不能写死成一条全局规则。DPT810样本文件名不是已确认的未来自动命名规范。

模板可按名称和修改日期供人识别；仅名称相同不能证明内容相同。内部版本校验建议见D08。文件名不合法、过长或路径越界必须指出字段和原因，不静默截断导致串号。结果目录可配置“直接存入目录”或“目录下按序列号建子目录”，具体实际目录未给出。

## 7. 任务状态约束

建议实现状态至少表达：待用户确认（未受理）、已受理／排队、暂停、已下发、执行中、成功、失败、取消请求中、已取消、结果待确认。分文件另记生成、保存、回传、预览与打印状态，不用一个success布尔值覆盖所有阶段。

待确认弹窗不占队列；下发与取消必须有明确胜出结果；打印失去回复进入待确认而非失败后自动重打；暂停不等于已取消；任务受理前失败不计为已执行；持久化失败不能先回复“已受理”。具体状态名和存储可由开发方调整，但不得丢失这些语义。
