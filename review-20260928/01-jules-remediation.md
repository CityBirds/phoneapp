# 给 Jules 的整改意见

日期：2026-09-28。审查目录：D:\York\phoneApp；代码基线提交：4f60d8c79d6ff6a505a6d0d459c9b81cbfc407ba。范围：用户提出的11个问题，以及直接相关的生成、预览、打印真实性。未修改业务代码，未启动业务服务或执行端，未向真实打印机发作业，未运行会写入现有业务数据库的全套测试。

## 结论

目前存在管理界面、终端页面和模板上传入口，但核心数据流仍以硬编码POA200样本为中心。管理界面的字段映射没有驱动手机表单与执行端生成。仅修饰页面或增加型号判断分支不能解决问题，应打通“实际模板 → 可编辑字段配置 → 发布版本 → 动态表单 → 服务端校验 → 指定模板生成 → 原文档转换预览”的完整流程。

优先级：P0为错文档、错误成功状态、错任务或错打印风险；P1为核心功能不可用／与业务要求不符。本报告的“已复现”仅指隔离探针明确运行过的行为，不能当作全程序端到端测试。

## 样本核对

新增990-Ex样本为真实.doc，当前电脑只读打开并导出一页检查，原文件哈希不变。Customer为YORK；Instrument为DPT-990-Ex；Inst. SN.为EX10260902；Date为8/28/2026；Test Flow为2L/min；温度22.1℃，湿度50%RH。测试表列为Test point Number、NIST Traceable Standard ℃ dp、Analyzer ℃ dp，共9个数据行。

## 逐项整改

### J01 执行端列表只反映正在运行的服务 — P1（含P0调度项）

证据：src/frontend/admin.js:105管理页面请求/api/workers?all=true，显示历史离线记录，且只在页面加载／切换时刷新。src/backend/server.js:179普通接口按15秒心跳过滤，但共享打印统计在过滤前使用所有历史记录。src/frontend/app.js:126未找到原选中终端时没有清空选择，:221只要存在对象就标“在线”；:345提交仅检查对象存在。src/backend/server.js:421未验证指定执行端的新鲜心跳，缺省还回退worker-local。

另：tests/test_e2e.test.js:54创建worker-pc01／worker-pc02，使用src/backend/db.js固定data/phoneapp.db；服务启动清理仅匹配部分测试ID和时间，不是隔离测试数据库。测试登记的终端可能污染实际界面；本轮未读取业务数据库来断言某条记录具体来源。

整改：当前监控／可选终端列表只显示有效会话中实际运行的执行服务，不预置虚构终端；历史设备身份可为审计保留，但不混入当前列表。显式停止立即失效，异常断开在可配置心跳期限后失效。后台刷新，提交时服务端再次校验；选择过期清空或禁用并保留表单，不静默换机。状态“就绪”须真实表示可接收该任务，不能把故障、断线或纯历史记录改成就绪。忙碌但服务仍在线与既有排队规则兼容，不为了隐藏离线条目而删除已受理任务。

共享打印：server.js:185按名称计数不能识别物理设备；同名不同机不能合并，异名同物理机必须可关联。维护physicalPrinterId与各执行端queueId的多对一关系，无法自动确定时人工绑定，共用物理队列。只登记实际开放的打印资源，不把全部检测结果自动当作授权资源。

关联：Q01—Q05、Q35—Q37。

### J02 发货地错误写入Customer — P0

证据：src/frontend/index.html:78写“发货目的地(Customer)”；server.js:87和:106把shippingLocation映射Customer；doc_processor.ps1:90、doc_processor.py证书分支均用发货地覆盖Customer；preview.js:73也使用location。

整改：shippingDestination仅用于已配置的业务及文件命名；Customer作为模板静态原内容保留，包括大小写。移除旧种子与已发布配置中的错误绑定，修复流程须有备份／迁移，不仅修改新建种子。不得批量覆盖用户其他自定义映射。以POA／DPT810／990原件各自Customer值作验收，不能统一写死YORK。

关联：Q06—Q07。

### J03 传感器序号重复填写且清单值被忽略 — P1

证据：index.html:90顶层sensor-sn输入；app.js:296同时允许编辑传感器备注；:356提交顶层sensorSn。doc_processor.ps1:131、:184用顶层sensorSn重新组成备注，覆盖用户在清单改的内容。Python回退同样处理。

整改：POA传感器序号只在清单传感器行提供一个明确的结构化输入，其他位置只读引用同一值。不要仅在自由备注中用字符串猜SN。不存在清单／传感器字段的模板，不显示该输入。传感器型号下拉用于命名，与清单规格PMT210SEN独立，不能因序号收敛而错误联动规格。

关联：Q08—Q09。

### J04 新增物料名称不能自定义 — P1

证据：app.js:323固定name='自选辅料'；:296名称仅文本输出，没有name编辑控件。隔离执行已复现。

### J05 设备序列号存在两份可冲突数据 — P0

整改：设备SN设置一个权威字段，证书、清单主设备SN和文件名统一绑定；重复展示采用只读联动。旧客户端／接口若提交两份冲突值，服务端拒绝并定位字段，不静默选一份。拒绝发生在任务受理、生成和打印之前；一致值及前导零正确保留。

关联：Q12—Q13。

### J06 温度湿度未形成填写和写回链路 — P0

整改：在各证书配置真实温度、湿度绑定，手机填写，服务校验持久保存，执行端按发布位置写回；单位不重复。不同模板实际位置、默认策略和精度分别配置。模板中没有的字段不虚构，已经存在且要求填写的字段不能漏掉。生成Word与其真实预览必须一致。

整改：DPT810不出现Customer输入，也不强制填写一个伪装成Customer的发货地；命名是否另需发货地按其配置决定。Customer保持原件。

### J09 无清单仍套用POA数据和传感器输入 — P0

证据：app.js:17固定POA packingItems，onModelChange只隐藏泵选项和改测试表；server.js:467—474总插入cert及packing两个文件；worker.js:150—157证书仅区分DPT810，其余都用POA证书，所有清单都用POA样本。管理端上传新模板不影响这条执行链。

整改：当前用户说明优先于旧文档“每台设备必定两份”的宽泛描述。POA已提供两份，DPT810和990当前各只有证书；实际发布组合包含什么就显示、校验、生成什么。没有清单时无packing字段、无清单预览页签、无清单任务记录／输出；无传感器绑定就无传感器输入。切型号必须隔离草稿值，不能携带POA隐藏字段污染提交。任务固定templateId、发布版本和实际文件，不用型号名字兜底到其他样本。

关联：Q20—Q23、Q31。

### J10 中文上传文件名乱码 — P1

证据：server.js:34上传中间件缺省配置，:259直接使用req.file.originalname作为存储／显示名；管理端回显该值。隔离使用本项目上传中间件和临时回环HTTP服务，上传990-Ex-EX10260902发货证书.doc，返回名称已乱码，与截图现象一致。该探针不写业务数据库。

整改：统一规定浏览器上传、服务解析、数据库、列表、下载的Unicode名称合同。在入口正确处理文件名编码；不得对所有名字无条件二次转码。显示原名与内部安全存储ID分离，真实扩展格式单独校验。已有乱码记录备份后可人工改名或重新上传，不能未经校验批量反向转码。支持中文／英文／括号／空格，下载名称和内容哈希往返一致。

关联：Q24—Q26。

### J11 字段匹配没有人工编辑且结果并非真实结构 — P0

证据：server.js:311把.doc二进制整体按utf16le转字符串，:316只取前100段，:320—322人为设tableIdx=0、rowIdx=floor(idx/2)、colIdx=idx%2。这不是Word表格解析。:331证书目标固定为六个标签，强加Customer、Sensor、Analyzer pv ppm，却漏掉温湿度和其他测量列。

admin.js:runTemplateAnalyze仅取candidates[0]展示，不提供增删字段、人工坐标绑定或候选选择；找不到显示“自动兼容”。saveMatchedRules保存的是全体候选matches，而不是用户确认的位置。worker.js未读取field_mappings。matcher.js的包含判断未排除空字符串，隔离探针确认空单元格可命中任意标签。

整改工作流：用户新增／删除需要配置的字段 → 选择单值／表格列等类型 → 真实解析原件 → 展示全部有效候选和上下文 → 用户确认值位置、列及数据行范围 → 缺失项人工绑定或保留不发布 → 试生成对照 → 发布 → 手机和执行端共同消费该固定版本。删除配置字段只停止对应表单输入／替换，不擅自删除模板正文。

解析必须区分标签位置与值位置，支持多表、合并单元格、段落、同名单元格和跨行标题。空文本不匹配。未知格式／解析失败显式报错，禁止“按标准表结构”猜位置。表格列必须绑定整列数据区域，不能用右邻单元格代表全部测试值。所有启用且未解决绑定的字段阻止正式发布；允许先保存草稿。

关联：Q27—Q32。

## 必须同时修复的关联问题

### J12 预览是重新画的示意图，不是Word预览 — P0

src/backend/preview.js:201只检查文件存在，然后按formData生成固定SVG。提供非Word字节文件也返回“预览”，已隔离复现；它还固定温湿度、布局和部分文本，可能与实际证书不同。server.js:631在预览异常后仍可标PREVIEW_READY。app.js:435在25次约17.5秒后停止轮询，成功状态也可提前结束。

必须转换实际生成并校验过的Word版本，产出完整PDF／图片；转换失败不能用合成证书兜底成功。页面展示阶段及错误，历史持久关联预览；刷新／重开不重新生成，仍能查到。转换故障重试转换，不重复生成。撤下“毫秒级／pixel perfect”等未经验证提示。

### J13 打印未实际执行即报告完成 — P0

worker.js:processPrintJob只校验打印机，然后POST状态并setTimeout一秒后PRINTED，没有实际文档打印调用。不能交付为真实打印。应完成指定原Word版本、打印队列、份数和系统作业关联；没有可靠出纸反馈就停留在可证实阶段。修复前不得把该代码的测试通过当作实体打印验收。

### J14 处理器失败可能交付未修改的模板；领取任务没有排他 — P0

doc_processor.ps1:37缺办公组件exit 0；word_engine.js失败回退后不检查processedSuccessfully就返回哈希；Python.doc回退可只保留复制文件再报告成功。生成必须在处理／校验失败时失败，不以文件存在替代字段正确。worker.processTask异常只日志输出，不回报明确子文件失败，可能造成页面久等。

server.js:587、:666待领取查询包含worker-local／worker-e2e通配，未看到原子领取与执行租约；worker启动及每秒轮询，异步调用没有防重入。多个执行端可能取得同一项，尤其打印。应固定目标、原子领取、持久去重、回报故障；不确定的打印结果不能重发。此项是代码风险分析，本轮没有实际制造重复打印。

### J15 测试在验证错误的替代品 — P1

tests/test_frontend.test.js主要断言HTML id存在；test_worker的生成测试主要看输出存在／模板哈希；test_e2e:145要求预览是.svg，:164只要求返回固定字段。它们不能证明真实字段位置、正确Word内容、动态表单或实体打印。E2E还可能写实际data目录，必须改用隔离数据库、临时目录和明确模拟外设。

补充发现：admin.js公开发送固定管理token，server.js:39允许hostname=localhost或该token绕过本机限定。不得将“仅协调主机管理”视为已验证；整改时依据实际来源及访问机制实现，不在报告中重复分发该凭据。

## 建议实施顺序及交付约束

1. 先停止虚假成功路径，建立子文件错误、真实模板引用和真实预览链路；隔离测试数据。
2. 建立模板发布数据模型：templateId／revision／documentKinds／fields／bindings／tableRegions／defaults／staticFields／namingRules。不同证书的行数、单位及可选清单从配置来。
3. 完成协调主机字段编辑与匹配发布界面，手机消费配置，服务按同一配置校验，执行端按同一映射写回；移除样本回退和固定两行分支。
4. 修复实时终端会话及物理打印机身份、排他调度和真实打印。
5. 跑本包回归用例，附Word内容／逐页预览／状态日志与实机证据；不能只提交页面截图。

本轮范围是整改，不需要重写整个系统。保持一个协调服务、多执行端、协调电脑管理界面、手机先选终端、保护模板、目录边界及已确认历史／覆盖规则。新规则优先：组合文件可缺省、Customer静态、单一序列号来源。上传新增990后不得因未配置映射而自动套POA生成。

本报告未执行全套现有测试，原因是它们会写固定业务data目录且可能调办公组件。已运行6类隔离探针，结果见evidence/probe-results.json；具体回归验收均见02-regression-tests.md，未标为通过。
