# 字段匹配需求与实现大纲

日期：2026-09-28。状态：用户已同意本文所述匹配策略，并要求并入第二轮复核包。本文将策略具体化；功能行为为交付要求，数据结构及模块划分为实现建议，不指定框架或承诺依赖兼容性已经验证。关联[复核报告](followup-review.md)，补充其中字段匹配和模板配置整改。未修改业务代码，未执行本文验收用例。

## 1. 目标与完整流程

用户定义字段 → 读取真实Word结构 → 推荐候选 → 用户确认值位置或表格区域 → 配置表单／默认值／选项 → 试生成并核对 → 发布固定版本 → 手机填写 → 服务端校验 → 执行端按绑定生成 → 转换实际原文档预览。

首次配置允许人工确认，日常生成按固定配置执行，不每次重新猜位置。协调服务电脑提供全部配置操作。增加已有能力范围内的型号、字段、选项和表格列不改代码。固定样本分支、伪坐标、未执行的候选选择和仅存候选列表均不符合此流程。

## 2. 字段用途与编辑类型

界面至少区分以下四类。内部建议将用途和输入控件分开，避免未来“写回Word的下拉字段”无法表达。

| 字段类别 | 用户配置 | 执行约束 |
| --- | --- | --- |
| 单值字段 | 显示名、内部键、输入类型、必填性、单位／格式、默认值来源、Word值位置 | 更新选定填写位置，不覆盖标签及整段无关内容 |
| 表格列 | 表格、表头、列、数据行范围／测试点身份、单位、默认来源、逐行校验 | 按行写入数据区域，保留表头、说明、合并格、其他列及版式 |
| 业务参数 | 类型、选项、适用模板组合、默认项、用途如命名 | 不要求Word位置，未声明写回时不能改正文 |
| 静态内容 | 保留模板内容；如有必要显式标记受保护区域 | 不显示为手机必填输入，不因名称相似自动替换 |

Customer属于当前证书静态内容。POA sensorModel属于命名业务参数；只适用POA配置，不自动改变清单规格PMT210SEN或传感器序号。设备序列号为一个权威值，可绑定证书、清单及命名的多个明确位置；其他展示只读引用，不建立多份可冲突数据。

删除字段配置表示停止显示／替换该变量，不删除原Word中的标签、表格行或静态正文。证书测试点数量来自模板已确认区域，不自动开放测试点增删；清单普通物料增删沿用既定规则。

## 3. 真正读取文档结构

支持真实.doc与.docx，不能把后缀改名视为格式转换。解析输出应包含文档、段落、表格和单元格身份，单元格内完整原文、合并关系、标签及邻近上下文。保留原始内容和用于匹配的规范化文本，二者分开保存。

同一单元格中的“NIST Traceable换行Standard ℃ dp”必须保留为一个完整表头。不得将Word二进制直接按utf16切片，再用片段序号推算行列。不能解析、嵌套结构不支持或定位不确定时明确提示，可保存草稿，但不能谎报坐标并继续写入。

实现建议：建立统一结构读取／写回接口，为实际可验证的Word处理方式提供适配器。具体组件、部署、XP支持需开发方先验证；不因本大纲采用结构模型就宣称所有复杂Word已支持。协调端解析与执行端写回必须对同一模板版本和位置描述有一致理解。

## 4. 候选匹配策略

1. 去除Word单元格结束符等结构控制字符，规范化换行、连续空格、大小写及标签末尾冒号；不删除型号、数值的有意义字符。
2. 优先比较规范化后的完整标签。
3. 区分基础名称与附加单位，允许用户不输入单位时找到候选，但展示原始完整表头、单位和“需确认单位”。℃ dp、mA、ppm不是等价单位，不能因为共有Analyzer就自动合并。
4. 支持用户明确配置的别名，如设备序列号对应Inst. SN.；保存别名来源，不能随意把业务字段与任何短词混同。
5. 有多个位置返回全部有效候选，附表格／段落、标签、当前值、上下文及匹配原因；用户选择后再绑定。
6. 空目标拒绝或要求补填，空文本不匹配；无候选显示未匹配并允许人工绑定。基础名称相近但单位／含义冲突时明确提示，不能标为已绑定。

界面使用“完整匹配”“别名匹配”“名称匹配，需确认单位”“多个候选”“无匹配”等可解释等级。固定0.8／1.0分数不应显示为算法置信概率。匹配成功只是候选发现，不等于已经识别整列或用户已确认。

## 5. 单值与表格列绑定

单值：分别保存标签位置和实际值位置。右邻格可作候选，但不能自动认定；同格标签＋值时需限定可替换范围。用户选择可回显原位置及样本值，确认不会覆盖标签。

表格列：选择真实表格、表头及逻辑列，再确认数据区域和测试点身份。预览逐行展示原模板标准值、单位、测试点及对应实测区域。表头、说明、页脚及合并装饰区不计数据行。不能只保存表头坐标或右邻格代替整列。

- POA200当前测试表1行；DPT810为10行；990为9行，均来自所选模板，而非if型号硬编码。
- 标准值初始取模板对应行且可修改；实测值不能从前次证书或测试用例自动填入。
- 标准值与实测值按同一测试点配对；提交行数、顺序和身份不符时明确报错，不截断或重复填充。
- 表格列绑定可人工指定，无须先匹配成功才能选择；用户改变候选或区域后，保存和试生成必须使用最后确认值。

手动绑定界面必须能选择真实单元格／段落／列／范围，并预览结果。“手动绑定”下拉空选项不算实现。应允许用户不具备Word坐标知识也能完成选择；首版可用结构化表格预览，不强制实现复杂可视化Word编辑器。

## 6. POA传感器型号下拉配置

协调主机提供字段显示名、内部键sensorModel、用途“仅命名”、控件“下拉”、适用POA模板组合、选项赋值文本框、拆分预览及可选默认项。

赋值文本以中文逗号或英文逗号分隔；去首尾空白、忽略空项、对完整文本去重并保持顺序。保留型号内部连字符、括号及大小写。正式发布时下拉应有有效选项，默认值若设置必须属于选项。当前分隔形式不支持在单个型号值中使用逗号；如以后需要，须增加逐项编辑方式，不能默默拆错。

该业务参数无需Word位置即可发布。手机从该发布版本加载选项，后端按同版本校验。非POA不显示、不提交、不默认填充、不参与文件命名；切换模板需清除或隔离旧表单数据。历史任务保留原选项值和发布版本。

## 7. 保存、试生成与发布

草稿可保留未完成绑定，但明确标状态。正式发布需验证：

- 启用且需写回的字段具有真实有效的位置；仅命名参数无需文档位置。
- 标签位置与值位置分开，表格列的数据区域完整，行对应关系成立。
- 多字段意外写入相同／重叠位置被发现，需调整；同一权威字段合法的多位置引用允许。
- 下拉默认值合法，必填／类型／单位／格式配置无矛盾；命名所引用的字段存在且适用。
- 试生成使用明确的测试输入，核对原Word及转换后的全部预览页；不可用表单重绘SVG作为证据。
- 模板原件哈希不变，静态内容和未绑定区域保持原样。

发布对象将Word、字段配置、绑定、选项、命名及文档组合固定到同一revision和内容校验信息。执行端取得相同版本后使用，不能兜底到另一个型号样本。草稿不得直接影响已发布版本；重新打开配置必须恢复用户编辑，不被自动标签数组覆盖。

模板内容或结构变化必须重新检查映射并试生成；旧任务保持受理版本。若旧版本不可得，应暂停说明，不能改用当前新版生成或打印。

## 8. 实现数据模型建议

以下是逻辑模型，不是已经存在的API或数据库表，也不是必须照抄的命名。

| 对象 | 关键数据 | 作用 |
| --- | --- | --- |
| TemplateRevision | templateId、revision、原件存储引用、真实格式、contentHash、草稿／发布状态 | 固定原件与版本 |
| DocumentStructure | revision、真实结构节点及稳定身份、原文、合并关系 | 匹配和人工定位的依据 |
| FieldDefinition | fieldId、displayName、purpose、inputType、适用范围、required、unit、format、defaultSource、options | 手机表单与后端验证共享定义 |
| Candidate | fieldId、标签锚点、建议值锚点／表格区域、原文、上下文、匹配理由 | 仅供选择，不直接作为发布绑定 |
| ConfirmedBinding | fieldId、revision、标签位置、值位置或tableRegion、用户确认状态 | 确定性写回的依据 |
| DocumentBundle | 已发布证书／可选清单、共享字段引用、命名规则、选项版本 | 有什么模板才生成什么文档 |
| TaskSnapshot | bundleRevision、固定输入、受理日期、所选执行端、文件版本 | 重试／历史保持原来含义 |

位置身份应在该固定Word版本内有效，不依赖浏览器列表序号。表格区域应有列、数据行身份和边界校验；每次执行验证目标仍符合绑定，不一致则失败而不是寻找“差不多”的位置。

## 9. 模块与实施顺序建议

1. **结构适配层**：替换server.js的二进制切片解析；输出真实结构及明确错误，用三份证书和POA清单验证。
2. **匹配层**：改造matcher.js，增加完整标签／单位／别名语义，返回可解释候选；不将所有包含关系视为可绑定。
3. **配置界面**：admin.js增加字段用途、类型、必填、默认、选项、候选选择、真实人工绑定、列范围及逐行预览；修改动作写入当前草稿状态。
4. **配置服务**：保存草稿和发布版本、验证位置与冲突、试生成、发布；请求接口能力应包括读取结构、匹配指定字段、保存确认绑定、试生成和发布。具体路由由开发方设计。
5. **动态表单**：app.js按发布定义渲染字段、测试表和可选清单，移除POA／DPT／990固定测试数组与硬编码选项；统一共享字段来源。
6. **校验与执行**：后台按任务固定版本检查字段适用性、行数和选项；worker及Word处理器读取指定版本的真实文件和ConfirmedBinding写回，不再读固定samples路径。
7. **真实预览及证据**：转换实际生成Word，绑定内容版本；分开记录生成／上传／转换失败，失败不得伪报成功。
8. **迁移与回归**：备份现有配置，对旧伪坐标标记需重新确认；不把旧matches直接转换成“已验证绑定”。原模板和历史任务不可批量删除，迁移可回退。

每步应有独立验证，但最终以新增模板无需改代码、从管理发布到手机填写再到实际Word结果正确为交付门槛。具体框架和Word处理组件在实现前按项目兼容要求核查，不把本大纲当作已完成选型。

## 10. 补充验收用例

沿用复核报告F01—F16；以下G01—G12补齐本次策略。全部未执行，测试数据只能用于测试。

| ID | 操作 | 预期 |
| --- | --- | --- |
| G01 | 单元格内NIST Traceable换行Standard ℃ dp，输入不带单位标签 | 识别同一完整表头，展示℃ dp及需确认信息，不拆成假单元格 |
| G02 | 输入Analyzer ppm，文档只含Analyzer mA／℃ dp | 不自动认定同一测量列，不以共有Analyzer显示已绑定 |
| G03 | 配置中文别名“设备序列号”对应Inst. SN.，文档有设备SN和参考仪器SN | 返回有依据的候选，确认设备值位置，不改参考仪器序号 |
| G04 | 人工选择非首个候选／同格值范围后保存、刷新、试生成 | 恢复最后确认绑定，只修改选定值，不改标签或其他候选 |
| G05 | 分别用POA1行、DPT81010行、9909行绑定测试列 | 行数与标准默认值来自模板，不依赖型号分支，实测初始不塞测试数组 |
| G06 | 提交缺行、多行、重复测试点或乱序数据 | 按明确行身份校验，不能错位、截断或复用上行值 |
| G07 | 建立POA仅命名下拉，配置两种逗号、空项、重复项及非法默认值 | 正确拆分预览、发布合法选项；非法默认阻止发布；无Word位置不算错误 |
| G08 | 两字段绑定同一值格，另一个权威SN字段绑定两个合法位置 | 前者提示冲突，后者作为明确共享引用可执行，生成两处一致 |
| G09 | 删除Customer输入配置或已有其他变量配置后生成 | 配置字段不再出现，模板原静态标签和值不被删除 |
| G10 | 修改模板结构／替换同名文件，旧绑定仍在 | 检出版本不一致，要求重新验证；旧任务不静默改用新文件 |
| G11 | 保存未完成草稿，同时手机读取已发布配置 | 草稿不影响正式表单；未完成绑定不能正式发布，完成试生成后才更新 |
| G12 | 新增一个未在代码出现过的型号与列配置并完成发布生成 | 无代码修改即可生成该原件格式，正确值和静态内容可核对；原Word与真实预览一致 |

验收证据须包含发布配置、确认绑定、输入、生成Word内容对照、全部预览页和操作记录；没有运行的测试不得写PASSED。
