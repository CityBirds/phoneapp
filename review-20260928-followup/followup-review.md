## 二、NIST Traceable Standard为什么不能绑定列

当前matcher.js做：换行／制表符转空格，去中英文冒号，压缩空白，转小写；完全相等计1.0，任何一方包含另一方计0.8。这两个固定分值是字符串匹配等级，不是统计置信概率，更不是Word位置有效性的保证。空值误匹配已修复，隔离验证为空候选。

截图的直接原因：admin.js:addMatcherField只push名称并设置candidates=[]，没有调用match-candidates接口或本地匹配器。因此新添NIST显示未命中，不是用户标签一定写错。

更深的问题：server.js:334仍整体读取Word二进制utf16le，再按正则抽取片段，tableIdx固定0，rowIdx=floor(idx/2)，colIdx=idx%2。只是取消原100条截断，并没有真实解析。实际990探针产生1026个片段，NIST Traceable与Standard被拆成两项；界面R390等是片段推算出来的，不是已验证的Word行号。

若显式调用当前匹配器，NIST会返回两个0.8候选，其中把Standard当成NIST Traceable的右邻值；仍不能得到真实标准值列。因此仅给新增按钮接一次请求不够。Analyzer pv ppm也会因包含Analyzer而得到0.8误匹配，这解释截图为什么不属于990的字段仍被标命中。

附带错误：admin.js:updateCandidateChoice函数体为空；renderMatcherTable在无候选时仍显示“已绑定”；saveMatchedRules一律取candidates[0]并存singleFields里的标签location，而非用户选择的值位置／列区域。手动绑定目前只有选项文字，没有实际选取位置功能。

整改要求：

1. 真实提取Word表格和段落，保留同一单元格跨行标题及单位，不把二进制片段编造成坐标。读不出来明确失败。
2. 新增字段后匹配并展示候选；用户选择必须更新状态和持久化；未绑定不得显示已绑定或正式发布。
3. 配置类型区分单值、表格列、下拉业务参数。标准值列绑定真实表格、列、数据起止行／测试点身份、单位与默认值，不采用右邻格当作整列。
4. 990的标准列应为9行，Analyzer ℃ dp实测列也是9行；DPT810为10行标准℃ dp／实测mA。表头中的单位不能丢失或误当成另一型号单位。
5. 重新打开配置读回用户保存的字段和选择，不重新用硬编码targetLabels覆盖。型号身份不要比较显示字符串；截图DPT-990-EX与后端只判'990'的分支不一致，导致回退到POA标签。
6. 执行端消费所选templateId、发布版本及确认映射；目前worker.js仍读samples固定路径。新增字段或上传模板不能只停留在管理页面。

## 三、传感器型号限定POA200且由管理端配置

当前app.js:onModelChange隐藏非POA的sensor-model-group，但submitTaskForm仍读取隐藏select并向所有型号发送sensorModel；server.js默认给所有型号PSR-12-223(封装）；naming.js:generateCertFilename无型号限制直接拼接。隔离调用复现了用户截图中的DPT810传感器后缀。

当前index.html:84选项直接写死PSR-12-223(封装）和PMT210SEN，管理配置没有选项赋值区域。

明确新增配置需求：在协调主机的POA200模板业务字段配置中支持：

| 配置项 | 约定 |
| --- | --- |
| 显示名／内部键 | 传感器型号／sensorModel |
| 字段类型 | 下拉选项 |
| 适用范围 | 当前POA200模板组合，不能污染DPT810／990 |
| 使用位置 | 文件命名参数；不写入证书正文，不自动覆盖清单PMT210SEN规格 |
| 选项配置区 | 管理员按英文逗号或中文逗号分隔填写，界面展示拆分后的选项预览 |
| 解析建议 | 两种逗号均分隔、去首尾空白、忽略空项、相同完整文本去重并保留顺序；不改型号内部字符、连字符及括号 |
| 默认值 | 若配置默认值，必须属于当前选项；必填性与默认项显式配置，不擅自给所有型号默认PSR |
| 保存／发布 | 存入模板配置并发布，手机从该配置生成下拉；历史任务保留受理时的选项值及版本 |

传感器型号是命名业务参数，源Word可能没有相应标签，因此不能要求它必须匹配一个Word单元格才能发布。只有声明写回Word的字段才需要文档位置；配置应区分“用于命名”与“写入正文”。

对非POA：不显示、不发送、不填充传感器参数，命名不包含传感器段及多余连字符。服务端校验模板适用性；伪造请求不得借字段污染文件名。对POA：校验提交值属于该发布版本选项。命名传感器型号与清单传感器序号、规格是三个不同概念。

现有固定测试值不是生产默认值：DPT810标准样本为[-89.00,-80.12,-70.81,-60.23,-50.82,-40.91,-30.45,-21.90,-12.26,10.25]，不是新代码的[-60,-50,...,30]。上一轮用例给出的实测数组、28.7、63.2用于测试，不能反过来作为软件固定业务数据。

## 四、其他尚未解决的高风险事项

- preview.js仍按表单画SVG，仅新增扩展名检查，不是转换实际Word；.doc后缀的任意字节仍可能被当作预览源。
- worker.js打印路径拼成print_job_ID_type.doc，未见把任务原件关联至该路径；文件不存在就跳过，PrintTo内部异常被吞，最后仍标PRINTED。去掉一秒定时器不等于真实打印成功。
- word_engine增加processedSuccessfully检查，但PowerShell缺组件依旧exit 0，Python.doc回退仍可能只复制文件就报告成功，错误闭环不完整。
- 待领取任务虽新增事务，查询仍含worker-local／worker-e2e通配；打印待领取也保留通配。不能仅靠新注释声明目标隔离／去重全部通过。
- 现工作区samples/990-Ex-EX10260902发货证书.doc显示已删除，而worker仍直接读取该路径；即使管理端上传了990也不能解决固定路径引用。未擅自恢复用户删除的文件。
