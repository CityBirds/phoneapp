基线日期2026-09-27，版本1.0。本包只整理需求、规则和用例，没有应用实现，不表示已有测试通过。文件不包含工具自动接入或监控配置。

## 版本升级与服务重启说明 (Upgrade & Service Restart)

**【重要提醒】** 每次拉取最新代码或进行系统功能升级后，必须关闭当前正在运行的旧协调服务控制台窗口（或结束对应的 Node.js 进程），并重新双击运行 `start_server.bat`（或 `启动协调服务.bat`）重启协调服务进程。

**升级重启必要性：**
1. 注册新的 API 路由（如 `/api/published-bundles`）；
2. 触发 SQLite 数据库表结构初始化与配置重载；
3. 避免手机端因旧版服务未注册新 API 路由而抛出 404 异常或导致模板下拉框为空。

## 可复制给Jules的任务说明

请基于本目录四份文档开发局域网多人设备任务系统。先阅读所有文档并列出兼容风险、阶段计划和选型建议，再按P0—P4推进。每台电脑需要执行端，Windows XP SP3 32位和Windows11 64位是硬要求，不能删掉XP支持或假设x86编译等于XP兼容。协调服务负责配置和预览，执行端负责生成与原Word打印。

必须完成用户指定字段辅助匹配、动态表单、测试值逐行表格、清单增删和保护行、条件命名及去重／覆盖／打印版本保护。现有能力内新增型号通过配置实现。不要把功能停留在静态UI或模拟数据。

规则D01—D12是未确认项，列出建议与受影响功能，不要伪称已获确认。可先完成不依赖这些决策的基础工作。不能访问XP、Windows、iPhone或打印机时，将对应测试标为未执行／缺少环境，提供可在现场运行的验证步骤，不以模拟结果替代实机证据。

每个阶段提交代码、变更摘要、已覆盖功能和规则编号、可复现测试命令及实际结果、截图或日志路径、未完成项与下一步。维护STATUS.md、DECISIONS.md和TEST-RESULTS.md。交付构建／安装／升级／回退与备份恢复说明。不要擅自上传业务模板到公开服务、发布真实证书或向真实打印机发送未经本次测试安排的作业。

## 给Antigravity的检查要点

此处是供用户使用的检查清单，不含外部工具API、安装或自动监控承诺。

- 根据提交版本核对功能编号、规则编号和用例记录；要求实际命令输出，不接受仅文字声称通过。
- 检查是否把XP执行端替换成只支持新系统的实现，是否把真实.doc处理替换成改后缀或占位输出。
- 检查新增型号是否依然需要写分支代码，测试表是否逐行映射、标准值默认与实测值是否混淆。
- 检查普通覆盖、旧文件副本命名方向、取消竞态、重启及断线后是否可能重复打印。
- 检查主设备／传感器保护行是否仅在UI隐藏按钮，服务及生成环节是否能拒绝无效数据。
- 检查预览与打印绑定内容版本；“已提交打印队列”不能当作“纸张已打印完”。
- 检查未定规则是否被擅自标为已确认，未执行测试是否被标通过，是否缺少原Word版式和实际设备证据。
- 发现阻塞时给出规则编号、涉及文件／提交、复现步骤、预期与实际、修复建议；不要代替用户确认业务规则。

## 验收记录要求

测试条目的状态统一使用：未执行、通过、失败、阻塞。待定规则另列阻塞原因；不要把“已经写了测试”视为通过。本包共71项用例，初始均为未执行。项目最终验收需关闭影响上线的D项，并提交各目标平台实机证据。

业务样本含设备编号、证书图章／签名等内容；本包仅在本机打包供用户交接，没有上传到Jules或Antigravity。用户分享本包时按实际使用范围管理。
